# Interface language

English is the default. Privacy and local data contains a language selector with a partial **Twi (draft)** option. The screen explicitly says that native-speaker review is still needed and missing translations use English. No new Twi wording was invented during the audit.

`lib/i18n/en.ts` contains typed English message keys. Readable English source strings serve as keys; the original short keys remain compatible. `t` substitutes named values as plain strings, so imported names never become markup or a second template. Components obtain their translator from `useI18n`. The React provider follows the local language setting without changing imported transactions, identifiers or rules. Preferences are remembered only when the user enables local storage.

`lib/i18n/tw.ts` is a partial typed record. Only its supplied draft labels are translated; all other text uses the English catalogue. The document keeps English as its primary language while this draft is partial. Translated labels use scoped `lang="tw"` markers, including navigation links, so long English fallback passages remain marked English. Dates and monetary formatting remain Ghana-oriented, with UTC date handling.

Category definitions store `labelKey` alongside their stable category IDs. The derived English `label` remains available to existing data consumers. UI labels use the key in the selected locale. Error and warning messages generated by the application use the same catalogue; imported descriptions and counterparties are never used as translation keys.

To add a translation, use an existing typed key in the partial locale file and have a fluent native speaker review the wording in context. Preserve named placeholders. Test the language selector, fallback, control names, mixed-language reading and narrow layouts. The source regression rejects untranslated JSX text and accessible label literals in components. A complete Twi translation and native review remain future work allowed by the original V1 specification.
